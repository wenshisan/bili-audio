# 哔哩哔哩音频播放器 PRD

## 1. 项目概述

### 1.1 产品定位
本项目是一款基于 Flutter 开发的第三方哔哩哔哩音乐播放器，专注于音乐内容的播放体验。通过集成智能歌词模糊匹配功能和优秀的后台播放能力，为用户提供专业的音乐收听体验。

### 1.2 核心价值
- **音乐专注**：仅支持音乐类短内容（< 15 分钟），过滤播客、长视频等非音乐内容
- **分P支持**：完整支持音乐合集分P播放，自动识别每个分P的歌曲信息
- **歌词支持**：智能模糊匹配歌词，支持多来源搜索和手动偏移校准
- **后台播放**：优秀的后台播放能力，系统级媒体控制集成，低功耗长时间播放
- **强大的本地管理**：边听边存自动缓存（默认 1GB），二次播放 0 网络请求，LRU 智能清理
- **Material Design**：遵循 Material Design 3 设计规范，支持浅色/深色主题切换和自定义配色方案
- **跨平台**：基于 Flutter，支持 Windows、macOS、Linux、Android、iOS

### 1.3 目标用户
- 喜欢在 B 站听音乐的用户
- 希望节省流量和电量的移动用户
- 需要歌词显示功能的音乐爱好者
- 希望脱离浏览器环境使用专用音乐播放器的用户

---

## 2. 用户场景

### 场景 1：音乐收听
用户在 B 站上发现喜欢的音乐视频，希望在不播放视频的情况下只听音频，并且能看到同步的歌词。

### 场景 2：音乐合集播放
用户收藏了一个包含 50 首歌曲的音乐合集（分P），希望连续播放所有曲目，每首歌都能自动匹配对应的歌词。

### 场景 3：后台长时间播放
用户在通勤、工作、运动时希望应用在后台持续播放音乐，锁屏后可通过系统媒体控制切换歌曲。

### 场景 4：歌词校准
自动匹配的歌词时间轴与音频不完全同步，用户希望手动调整偏移量以获得最佳体验。

### 场景 5：本地歌单管理
用户希望将喜欢的音乐内容收藏到本地播放列表，按心情、场景分类管理，方便随时播放。

## 3. 核心功能

### 3.1 内容获取

#### 3.1.1 B 站音乐内容搜索
- **搜索入口**：支持关键词搜索 B 站音乐内容
- **内容过滤规则**：
  - **时长限制**：仅显示时长 ≤ 15 分钟的内容，自动过滤播客、长视频
  - **分区过滤**：优先音乐区（28）、娱乐区音乐分类，可配置其他分区
  - **分P识别**：支持多P视频，展示总P数，每个分P视频自动继承主视频的时长限制
  - **内容类型**：支持普通视频音频流、音频区专属内容
- **搜索结果展示**：
  - 封面缩略图
  - 标题（自动优化显示，见 3.1.3）
  - UP 主信息
  - 播放量、点赞数等统计信息
  - 时长 + 分P数量标识
  - 已过滤标记（时长超限内容灰显或隐藏）
- **分页加载**：支持下拉加载更多结果

#### 3.1.2 音频流提取
- **使用 B 站 API**：通过视频/音频 API 获取音频流地址
- **音质选择**：支持多档位音质选择（64K/128K/192K/320K/Dolby），需登录解锁高音质
- **缓存机制**：音频流 URL 有时效性（约 2-6 小时），需要缓存并在过期前自动刷新
- **无感续播**：流 URL 过期时后台自动刷新，不中断播放体验

#### 3.1.3 自动优化歌名显示（核心特性）

B 站视频标题往往包含大量营销性、描述性噪声，影响阅读体验和歌词匹配。应用内所有展示歌曲信息的地方（搜索结果、播放列表、通知栏、锁屏）都使用优化后的歌名。

**处理流程**：
1. **原始标题保留**：始终保存 B 站原始标题，用户可查看
2. **标题清洗**：应用清洗规则提取核心信息（歌名 + 歌手）
3. **优化显示**：界面展示清洗后的结果，格式统一为 `歌名 - 歌手`
4. **用户修正**：支持手动编辑歌名/歌手，修正结果持久化

**清洗规则**（与歌词匹配共用）：
- **去除括号修饰**：删除 `【】` `[]` `()` `「」` 中的内容，常见模式：
  - 音质标记：`【Hi-Res】` `【无损】` `【320K】` `【FLAC】` `【DSD】`
  - 视频类型：`【官方MV】` `【4K】` `【60帧】` `【HDR】` `【杜比全景声】`
  - 翻唱标记：`【翻唱】` `【cover】` `【Cover】` `【カバー】`
  - 字幕标记：`【中字】` `【日语】` `【罗马音】` `【歌词】`
  - 其他修饰：`【完整版】` `【Live】` `【现场】` `【纯享版】` `【伴奏】`
- **识别分隔符**：按优先级拆分歌名与歌手
  - ` - ` `—` `｜` `|` `/` (歌名在前，歌手在后)
  - `《歌名》歌手` 或 `歌手《歌名》`
- **去除前后缀**：
  - 前缀：`【中字】` `【日语】` `完整版` `高清` `官方`
  - 后缀：`MV` `歌词版` `伴奏` `纯音乐` `Instrumental`
- **伴奏/纯音乐识别**：标题包含 `伴奏` `纯音乐` `Instrumental` 时标记为"无歌词"，不搜索歌词
- **繁简转换**：统一转简体中文（用于匹配，显示保持原文）
- **规范化**：
  - 全角转半角（英文、数字、标点）
  - 去除多余空白（连续空格、首尾空格）
  - 统一大小写（英文歌名首字母大写）
- **兜底策略**：
  - 使用分P标题（多P视频中分P标题通常更准确）
  - 使用视频标签（tag）中的歌手名、歌曲名
  - 使用 UP 主名作为候选歌手（当无法识别歌手时）

**清洗配置**：
- 规则以 JSON 配置文件维护（`assets/config/title_cleaning_rules.json`）
- 支持正则表达式匹配模式
- 版本更新时可远程下发规则更新（可选）
- 用户可在设置中查看/禁用部分规则

**展示示例**：

| B 站原始标题 | 清洗后显示 |
| --- | --- |
| 【Hi-Res】周杰伦 - 晴天【无损音质】 | 晴天 - 周杰伦 |
| 《夜曲》- 周杰伦 官方MV【4K修复】 | 夜曲 - 周杰伦 |
| 【翻唱】告白气球 \| 祈Inory【Cover】 | 告白气球 - 祈Inory |
| Taylor Swift - Anti-Hero (Official Music Video) | Anti-Hero - Taylor Swift |
| 【中字】YOASOBI - アイドル / Idol 完整版 | アイドル - YOASOBI |

**双重用途**：
- **界面显示**：提升视觉体验，信息密度更高
- **歌词匹配**：清洗后的歌名/歌手直接用于歌词搜索，提高匹配成功率（见 3.3.2）

### 3.2 播放功能

#### 3.2.1 基础播放控制
- **播放/暂停**：标准播放控制
- **进度条拖拽**：支持任意位置跳转，显示时间和歌词预览
- **倍速播放**：支持 0.5x - 2.0x 倍速调节（0.5x / 0.75x / 1.0x / 1.25x / 1.5x / 2.0x）
- **音量控制**：支持音量调节和静音
- **定时停止**：支持设置倒计时（15/30/60 分钟或播完当前歌曲后停止）

#### 3.2.2 播放模式（客户端级别管理）

所有播放模式由客户端 `PlaybackQueue` 类统一管理，不依赖 just_audio 内置的 shuffle：

| 模式 | 行为 |
| --- | --- |
| **顺序播放** | 按队列顺序播放，播完最后一首停止 |
| **列表循环** | 按队列顺序循环播放，播完最后一首回到第一首 |
| **单曲循环** | 重复播放当前歌曲 |
| **随机播放（基础）** | 随机打乱队列，不重复直到所有歌曲播完一轮，然后重新打乱 |
| **随机播放（智能）** | 加权随机，避免同一歌手连续出现，降低最近播放歌曲的权重 |

**分P处理**：
- 多P视频的每个分P视为独立曲目
- 随机模式下可配置"分P连续播放"：同一视频的分P保持顺序，作为一个整体参与随机

**模式切换**：
- 切换到随机模式时立即生成随机队列，当前歌曲保持不变，后续按随机顺序播放
- 从随机切回顺序时恢复原始队列顺序
- 随机队列在应用重启后恢复（持久化随机种子或队列索引）

**播放完成行为**：
- 顺序播放：播完停止，显示"播放完毕"
- 列表循环 / 随机播放：自动循环，无限播放
- 单曲循环：无限重复当前歌曲

**智能跳过**：
- 播放失败（流 URL 失效、网络错误、版权限制）自动跳到下一首，最多重试 3 次
- 仅离线模式：只播放已缓存的歌曲，自动跳过未缓存项

#### 3.2.3 播放列表与队列管理
- **当前播放队列**：显示完整队列，高亮当前播放项
- **队列来源**：
  - 从歌单播放：显示歌单名
  - 从搜索播放：显示搜索关键词
  - 从历史播放：显示"播放历史"
- **分P自动播放**：多P视频按分P顺序自动切歌，每个分P独立匹配歌词
- **分P信息展示**：显示当前分P序号、标题、所属视频
- **上一曲/下一曲**：
  - 顺序/循环模式：按队列顺序切换
  - 随机模式：按已生成的随机队列切换，支持"上一曲"回退到随机队列中的前一首
  - 智能识别分P边界
- **队列编辑**：
  - 拖拽排序（顺序模式下生效，随机模式下不可拖拽）
  - 移除单个或批量项目
  - 插入到下一首播放
  - 清空队列（保留当前播放）
  - 保存队列为歌单
- **播放历史追溯**：显示"播放过的"和"即将播放"两个区域（随机模式下显示已播放的随机顺序）

#### 3.2.3 后台播放（核心特性）
- **系统通知栏控制**：
  - 显示封面、歌名、歌手、分P信息
  - 播放/暂停、上一曲、下一曲按钮
  - 进度条实时更新
  - 支持通知栏歌词滚动（Android）
- **锁屏控制**：
  - 系统锁屏界面集成媒体控件
  - 显示封面与歌曲信息
  - 支持耳机线控、蓝牙控制
- **媒体会话集成**：
  - 集成系统媒体会话（Media Session / MPRIS）
  - 支持系统快捷键控制（媒体键）
  - 与其他媒体应用协同（自动暂停/恢复）
- **低功耗优化**：
  - 后台播放仅解码音频流，不解码视频
  - 智能网络请求合并，减少唤醒
  - 支持 Doze 模式与后台限制豁免申请（Android）
  - 播放时防止系统休眠，暂停时自动释放
- **断点续播**：
  - 自动保存播放位置、列表、播放模式
  - 应用重启后恢复上次播放状态
  - 支持多设备进度同步（需登录，P2）

### 3.3 歌词显示与模糊匹配（核心特性）

#### 3.3.1 歌词来源
按优先级依次尝试，任一来源命中且评分达标即停止：

| 优先级 | 来源 | 说明 |
| --- | --- | --- |
| 1 | 本地缓存 | 已匹配过的视频直接读取，含用户校准的偏移量 |
| 2 | B 站 CC 字幕 | 部分音乐视频自带字幕，可转换为 LRC |
| 3 | LRCLIB | 开源歌词库，提供公开 API，支持按标题/艺人/时长检索 |
| 4 | 其他第三方歌词源 | 以插件形式接入，默认关闭，由用户自行启用 |
| 5 | 本地导入 | 用户手动导入 `.lrc` 文件 |

#### 3.3.2 标题清洗
B 站视频标题噪声多，匹配前需提取“歌名 + 歌手”：
- 去除括号类修饰：`【】`、`[]`、`()`、`「」` 中的“官方MV”“高音质”“无损”“4K”“Hi-Res”“翻唱”“cover”等
- 去除常见前后缀：“【中字】”“完整版”“Live”“伴奏”等（伴奏/纯音乐标记为无歌词）
- 识别分隔符拆分歌手与歌名：` - `、`—`、`/`、`|`、`《》`
- 繁简转换、全角转半角、统一大小写、去除多余空白
- 兜底：使用分 P 标题、视频标签（tag）、UP 主名作为候选歌手
- 清洗规则以配置文件维护，便于后续迭代

#### 3.3.3 模糊匹配评分
对每个候选歌词计算综合得分 `score ∈ [0, 1]`：

```
score = 0.55 × 标题相似度 + 0.25 × 歌手相似度 + 0.20 × 时长相似度
```

- **标题相似度**：归一化 Levenshtein 距离与 Token 集合 Jaccard 取较大值；拼音相似度作为中文补充
- **歌手相似度**：多歌手按 `、` `&` `feat.` 拆分后取最大匹配；缺失时该项权重并入标题
- **时长相似度**：`max(0, 1 - |Δt| / 10s)`，时长差超过 10 秒记为 0
- **判定阈值**：
  - `score ≥ 0.80`：自动采用
  - `0.60 ≤ score < 0.80`：采用但标记“可能不准确”，提示用户确认
  - `score < 0.60`：不自动采用，展示候选列表供用户手动选择

#### 3.3.4 时间轴对齐
- **整体偏移**：支持 ±0.1s / ±0.5s 步进调整，按视频（BV + 分P）持久化
- **时长缩放**：当歌词总时长与音频时长差异较大且线性相关时，提示是否自动缩放
- **前奏检测（P2）**：基于首句时间与音频能量起点估算初始偏移

#### 3.3.5 歌词展示
- **全屏歌词页**：当前行高亮、居中滚动，支持逐字歌词（若来源提供）
- **点击跳转**：点击任意歌词行跳转到对应播放位置
- **双语歌词**：原文与翻译分行显示，可切换
- **迷你歌词**：播放栏单行显示；桌面端支持悬浮桌面歌词（P1）
- **样式设置**：字号、对齐方式、高亮颜色

#### 3.3.6 手动修正
- 搜索面板：用户可修改关键词重新搜索并从候选中选择
- 标记“无歌词”：避免重复搜索
- 修正结果写入本地缓存，后续播放直接命中

### 3.4 账号与收藏

#### 3.4.1 登录策略（按需登录）
应用支持**免登录使用核心功能**，仅在必要时才提示登录：

**无需登录即可使用**：
- 搜索音乐内容
- 播放基础音质（64K/128K）
- 查看歌词、调整偏移
- 创建本地歌单
- 边听边存缓存
- 播放历史记录

**需要登录才能使用**（触发时弹出登录提示）：
- 播放高音质（192K/320K/Dolby）时提示"登录解锁高音质"
- 播放会员专属/需登录的内容时提示"此内容需要登录"
- 访问"我的收藏夹"时提示"登录后同步 B 站收藏"
- 关注 UP 主时提示"登录后查看 UP 主投稿"
- API 返回 -101（未登录）或 -403（权限不足）时自动引导登录

**登录入口**：
- 设置页"账号"区域（显示"点击登录"或已登录用户信息）
- 功能受阻时的弹窗引导（"立即登录"按钮）
- 首次启动时不强制登录，无弹窗干扰

#### 3.4.2 扫码登录
- **登录方式**：使用 B 站 TV 端扫码登录（二维码 + 轮询确认）
- **登录流程**：
  1. 获取登录二维码（qrcode_key）
  2. 展示二维码，提示用户用 B 站 APP 扫描
  3. 轮询登录状态（未扫描/已扫描/已确认/已取消/已过期）
  4. 登录成功后获取 Cookie（SESSDATA、bili_jct、DedeUserID）
  5. 存储到系统安全存储（Keychain/Keystore）
- **登录状态**：
  - 显示用户头像、昵称、等级
  - 支持退出登录（清除 Cookie）
  - Cookie 过期时自动检测并提示重新登录

#### 3.4.3 收藏夹同步
- **收藏夹同步**：读取用户 B 站收藏夹（仅音乐类内容，自动过滤 > 15分钟的项目）并导入为播放列表

#### 3.4.4 UP 主订阅
- **UP 主订阅**：关注 UP 主后可浏览其音乐类投稿列表

#### 3.4.5 本地歌单（无需登录）
- 创建、重命名、删除、排序本地歌单
- 歌单封面自定义（从歌曲封面选择或自定义上传）
- 支持歌单导入/导出（JSON 格式）
- 歌单内音乐去重、批量移动、拖拽排序
- 智能歌单（自动收集：最近播放、最常播放、本周新增）

#### 3.4.6 播放历史（无需登录）
  - 记录每次播放时间、播放进度、完成度
  - 按日期、歌手、歌单来源筛选
  - 支持清空历史、删除指定项
  - 历史统计：总播放时长、最爱歌手、播放热力图

### 3.5 离线缓存与本地管理（核心特性）

#### 3.5.1 边听边存（自动缓存）
- **智能缓存策略**：播放时自动缓存音频流，无需手动下载
- **首次播放**：从网络流式播放的同时写入本地缓存
- **二次播放**：直接读取本地缓存，完全离线，0 网络请求
- **缓存完整性**：音频 + 封面 + 歌词 + 元数据（标题、歌手、时长、分P信息）一并缓存
- **后台缓存**：支持在播放列表中标记"缓存"，后台自动下载

#### 3.5.2 缓存配置
- **默认大小**：1GB
- **可调范围**：100MB - 20GB（或无限制）
- **存储位置**：可自定义（移动端支持 SD 卡）
- **LRU 清理**：缓存满时自动清理最久未播放的项目
- **保护机制**：本地歌单内的音乐标记为"已收藏"，不参与自动清理

#### 3.5.3 缓存管理界面
- **缓存总览**：
  - 已用空间 / 总空间（饼图）
  - 已缓存音乐数量
  - 节省流量统计（累计）
- **缓存列表**：
  - 按歌单、歌手、时间筛选
  - 显示每首歌的缓存大小、缓存时间
  - 支持手动删除单个或批量清理
- **批量操作**：
  - 一键缓存歌单内所有音乐
  - 清理未收藏的缓存
  - 清理 N 天未播放的缓存
  - 导出缓存（打包为可分享格式，P2）

#### 3.5.4 网络优化
- **缓存命中优先**：播放前先检查本地缓存，命中则完全不访问网络
- **流 URL 懒刷新**：缓存的音乐无需刷新流 URL，仅在播放未缓存内容时请求
- **预加载策略**：播放列表中下一首自动预加载（可配置关闭）
- **网络状态感知**：
  - WiFi：自动缓存
  - 移动网络：仅播放当前，提示是否缓存
  - 无网络：仅显示已缓存内容

## 5. 技术方案

### 5.1 技术栈
- **框架**：Flutter 3.x / Dart 3
- **状态管理**：Riverpod
- **网络**：dio（统一处理 Cookie、Referer、User-Agent、WBI 签名）
- **播放**：just_audio + audio_service（后台播放与系统媒体控制）
- **缓存**：just_audio 的 LockCachingAudioSource，支持边播边缓存，缓存键为 `bvid_cid_quality`
- **本地存储**：
  - drift（SQLite）：歌单、历史、歌词缓存、偏移量、缓存索引
  - 文件系统：音频文件、封面图片、歌词文件
- **路由**：go_router

### 5.2 分层结构
```
lib/
├── data/          # B 站 API、歌词源、数据库、Repository
├── domain/        # 实体、歌词匹配算法、PlaybackQueue 管理（纯 Dart，可单测）
├── features/      # search / player / lyrics / library / settings / queue
└── core/          # 网络、日志、主题、工具
```

### 5.3 核心模块设计

#### 5.3.1 PlaybackQueue（播放队列管理）
- **职责**：统一管理播放模式、队列顺序、随机算法
- **状态**：
  - 原始队列（用户添加的顺序）
  - 当前播放队列（可能是随机打乱后的）
  - 当前播放索引
  - 播放模式（顺序/列表循环/单曲循环/随机/智能随机）
- **操作**：
  - `next()` / `previous()`：根据模式返回下一首/上一首
  - `shuffle()`：生成随机队列（基础或智能算法）
  - `insert()` / `remove()` / `reorder()`：队列编辑
  - `setMode(PlayMode mode)`：切换播放模式
- **持久化**：播放模式、随机种子、当前索引存入数据库

#### 5.3.2 歌词匹配模块
- 以 `LyricsProvider` 接口抽象各歌词来源，便于新增或禁用
- 标题清洗、相似度计算、评分为纯函数，覆盖单元测试
- 维护一份”B 站标题 → 期望歌名/歌手”测试集，用于回归评估匹配准确率

## 6. 合规与风险

| 风险 | 说明 | 应对 |
| --- | --- | --- |
| 非官方 API | B 站接口可能变更或触发风控 | 接口层隔离、请求限频、错误降级与快速更新 |
| 免登录使用限制 | 未登录时搜索可能触发风控（-412），播放仅能获取低音质 | 生成并缓存 buvid3 设备指纹，模拟正常客户端行为；明确告知用户登录可解锁高音质 |
| 版权 | 音频与歌词版权归原作者/平台所有 | 仅提供播放与个人缓存，不提供分享/再分发；应用内声明非官方 |
| 账号安全 | 登录凭据敏感 | Cookie 使用系统安全存储（Keychain/Keystore），不上传任何服务器 |
| 第三方歌词源 | 部分来源无公开授权 | 默认仅启用 LRCLIB 与 B 站字幕，其他来源由用户自行开启 |
| 匹配误判 | 翻唱、同名歌曲易误匹配 | 时长约束 + 低分提示 + 手动修正 |

> 本项目为个人学习用途的第三方客户端，与哔哩哔哩官方无关。

## 8. 验收指标
- **按需登录**：未登录状态下可完成搜索、播放、歌词、缓存、本地歌单全流程，启动及常规使用中不出现登录弹窗；仅在 3.4.1 列出的场景触发登录提示
- **内容过滤准确性**：搜索结果中 > 15 分钟的内容过滤率 100%，分P视频能正确识别每个分P的独立时长
- **缓存功能**：
  - 首次播放时自动缓存成功率 ≥ 99%
  - 二次播放缓存命中率 100%，0 网络请求
  - 1GB 缓存空间可容纳约 200-300 首歌曲（按 128K 码率估算）
  - LRU 清理准确，不误删"已收藏"音乐
- **歌词匹配准确率**：测试集（≥ 200 条热门音乐视频）歌词自动匹配准确率 ≥ 85%，误匹配率 ≤ 5%
- **歌词对齐精度**：偏移校准后歌词与演唱误差 ≤ 0.3s
- **后台播放稳定性**：连续后台播放 6 小时无崩溃、无明显内存增长（< 20MB）、无音频中断
- **分P切换体验**：分P间切换延迟 < 0.5s，歌词自动切换到对应分P
- **播放模式正确性**：
  - 随机模式一轮内不重复，所有曲目均被播放一次后才重新打乱
  - 智能随机下同一歌手连续出现概率 < 10%（队列中该歌手占比 < 50% 时）
  - 随机模式"上一曲"能准确回退到上一首实际播放的曲目
  - 模式切换、应用重启后队列与当前曲目保持一致
- **系统集成完整性**：通知栏、锁屏、媒体键、蓝牙耳机控制全部正常工作
- **流 URL 自动刷新**：播放 3 小时以上，流 URL 过期时自动无感刷新成功率 ≥ 99%（仅针对未缓存内容）
- **核心模块测试覆盖率**：标题清洗、评分算法、分P解析、缓存管理、PlaybackQueue 单元测试覆盖率 ≥ 90%
